GitHub Pages：https://kangkangtian181-lang.github.io/sany-ai-order-demo/

## 如何打开

任选一种方式即可：

1. **直接双击**  
   打开本目录下的 `index.html`（同目录需保留 `styles.css`、`app.js`）。

2. **本地静态服务（推荐，避免个别浏览器对 `file://` 的限制）**

   ```bash
   cd /workspace/sany-ai-order-demo
   python3 -m http.server 8080
   ```

   浏览器访问：http://127.0.0.1:8080/

数据保存在浏览器 `localStorage`（键名与原站一致：`v3_orders` / `v3_persons` / `v3_corps` / `v3_cfg` / `v3_fabPos` / `v3_drawerTop` / `v3_orderStore`）。清站点数据后会恢复内置示例。

## 相对原站改了什么

### 样式与结构

- 统一设计令牌：间距、圆角、阴影、焦点环；主色仍是蓝橙，饱和度更克制，正文/辅助色对比更好。
- 顶栏、侧栏、卡片、步骤条、表格层级更清楚；表格支持浅斑马纹、表头吸顶、状态色标签。
- 表单分区、OCR 区、资产合计卡片对齐更规整；底部操作栏半透明固定，不抢主内容。
- AI 抽屉改为约 520px（原约 640px），减少遮挡；现代圆角与头部渐变保留，但不堆特效。
- 去掉大片内联 `style` / `onclick`，改为语义化 class（如 `toolbar-actions`、`ocr-block`、`data-toast`）。
- 未引入原站 Coze Analytics / APM 脚本。
- 1280px 及以上桌面为主要适配目标；约 1100px 以下侧栏改为顶置横滑，抽屉拉满宽，保证大致可用。

### 交互小改进（逻辑仍等价）

- 列表「查询 / 重置」原站按钮无实际过滤，本版按关键字过滤当前表格（不改示例数据）。
- 状态 Tab 仍只切换高亮，不按状态过滤——与原站一致。示例订单状态为「已保存」，与 Tab 文案（待处理/已放款等）不是同一套枚举。
- 新建订单时会重置资产完整性提醒条（原站重置向导后该条可能残留上一次结果）。
- 侧栏点击「客户/担保」父级：原站会落到「法人客户」；本版进入该分组第一项「个人客户」。

## 与需求说明不一致、按原 JS 落地的地方

- **尽调信息、信审材料**在原站位于第 4 步「上传附件」，而不是第 2 步。本版跟随原 JS。
- 导航文案沿用原站「法人客户」（不是「企业客户」），顶栏仍是 Logo + 贷款试算/下载中心/小程序，左栏才是订单/个人/法人切换。
- 「委托挂靠」选项保持禁用；添加担保方 / 反担保 / 批量导入资产等按钮仍为演示 toast，真正的担保卡片由 AI 解析带入。

## 已知演示限制

- 这是前端 Demo，不会连接真实信贷核心或 OCR 服务。
- AI 接口留空时走 `localParse` 本地规则，识别能力有限；接 OpenAI 兼容地址后才走大模型（浏览器直连可能遇到跨域，原站同样如此）。
- 请勿在演示环境粘贴真实客户敏感信息。
- 身份证/执照上传只做本地压缩预览与分类，不做真实 OCR（除非配置了带视觉能力的模型）。
- 部分能力仅为示意：更新客户信息、关联 CRM、查看尽调、添加附加品、下载模板、挂靠方/担保方/回款等侧栏模块。
- `localStorage` 有容量上限，大量图片附件可能无法持久化到订单材料库。
- 示例数据中的身份证号、手机号等均为原 Demo 虚构素材，仅供联调界面。
- 本地规则解析：原站要求「挂靠方 / 挂靠公司」前缀才能抽出公司名，但「填入示例」原文是「挂靠郑州智运互联物流科技有限公司」。本版将前缀视为可选，以便示例能带出挂靠方。


## 建议自测路径

1. 打开页面，在侧栏切换「订单管理 / 个人客户 / 法人客户」，表格应有示例数据。
2. 点「＋ 新增订单」，走完 4 步（产品 → 客户担保 → 添加资产并保存 → 尽调/材料），再点「提交/保存」。
3. 打开右下角 AI 录单助手，点「填入示例」→「AI 智能解析」，再分别「填充到录客户 / 录订单」，核对 AI 置信度标记。
4. 保存后应回到订单列表并看到新单。
